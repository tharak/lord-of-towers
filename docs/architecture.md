# Architecture

Gameplay and UI use Bevy ECS. `model.rs` owns shared data contracts, independent of meshes and materials. Every application entity has Name and EntityKind; match-scoped entities have MatchEntity. The live F3 inspector queries ECS directly instead of maintaining a duplicate registry.

`SimulationPlugin` owns setup, restart, movement, combat, production and victory. `GatheringPlugin` owns finite deposits, automatic pickup equipment into empty unreserved slots, local navigation, cargo transfer and fading carrier trails. `EquipmentPlugin` owns commands, reserved tower orders, equipment transfer and derived attributes. `PlayerInteractionPlugin` owns mouse/touch selection, contextual equipment/recipe UI and two-finger camera input. `InfluencePlugin` samples territory. Presentation owns primitive visuals, camera and the hideable HUD.

Fixed systems run at 30 Hz and scale simulation time with speed. Their order is Spawn → PlayerCommands → Index → Target → EquipmentNavigation → CombatTarget → Movement → Combat → Capture → Gathering → EquipmentTransfers → Production → Attributes → Influence → Victory. Tower defense overrides order/gathering navigation. Cargo and order travel prevent generic enemy pursuit but permit firing in range. Combat queues homing projectiles; damage resolves on impact. Cooldowns and one-second shooting pauses remain; energy is removed.

Pause, hidden tabs and victory stop simulation. Restart runs in PreUpdate and replaces match entities, clearing pending player commands, selections and orders. HUD visibility and camera/inspector infrastructure survive restart. Equipment reservation cleanup also handles dead participants without waiting for active simulation.

Towers have fixed radius 15. Their circles indicate territory and tower alerts. NPC towers first equip nearby empty slots and then produce FIFO five-unit births. Player tower production requires an explicitly selected five-unit recipe. Birth stats start at two plus recipe points; only equipped units activate stat bonuses. See [equipment](equipment-contracts.md) and [gathering](gathering-contracts.md).

All visuals use Bevy primitive meshes: stacked tower-health cubes, beacon spheres, deposit/cargo/stock torus stacks, equipped element spheres and faction-colored projectiles. A player-tower indicator appears at five available units. Visual children carry no inventory or combat authority. Contextual panels appear only for a selected friendly unit/tower. The minion panel is a three-by-five element button grid: equipped choices are outlined, stocked choices work in every row, and clicking equipped gear moves it immediately into cargo for return. The bottom bar has pause/play, three speeds and restart; HUD toggle stays accessible when hidden. Two-finger pan/pinch and keyboard camera controls remain.

GitHub Actions performs native compilation and release WebAssembly compilation, deploying main to GitHub Pages. No automated tests or runtime smoke checks are used. Runtime problems are investigated when the user reports them.
